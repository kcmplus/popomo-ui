1 项目目标与交付边界

建设面向移动端优先、兼容 PC 的手机壳定制网站。用户通过照片、精选模板或 AI 建立底图，叠加贴图与文字，保存私人草稿或经明确授权公开分享，再选择设备打印或快递到家完成订单。

本说明面向产品、前后端、测试和设备对接团队。已确认的产品规则使用“必须”；接口、数据结构和生产运维方案为建议实现，需要技术评审后落地。

类别基线与正式开发要求
视觉与流程当前公开站点为版本35。保留紫色、近黑色、白色与适量毛玻璃风格，默认英文，可切换简体中文。
当前展示实现静态 HTML / JS；账户、作品、订单等依赖浏览器存储；AI 生成、快捷登录及支付为展示流程。不能据此认定真实服务已接通。
正式交付需实现真实身份认证、跨设备持久化、公共作品库、AI任务、支付回调、设备履约、物流及后台管理。
非本次已确定事项真实机型与颜色资源、设备在线数据、支付商户参数、AI收费、物流服务商、生产工艺参数与退款规则均需项目方提供或评审。

参考入口：公开站点。实现依据还包括 phone-models.js、flow.js、editor.js、design-store.js、sharing.js、community.js、order-store.js、fulfillment.js 与 printers.js。

3 机型颜色与模型联动的强制规范

此项为核心验收门槛。 brandId → modelId → colorId → variantId → 渲染资源，是同一条数据链。颜色选择不是只修改色块标签，也不能对整张手机壳图做 CSS 染色。后台负责上传每个机型及颜色的真实外形和硬件图层。

字段含义及约束
modelId / brandId稳定唯一标识。前端不可用型号名称作为数据库主键。
colorId / colorName / swatch该机型支持的颜色；名称中英双语。色块用于选择，不代替实物渲染。
variantId / assetVersion机型与颜色组合的唯一资源版本，写入设计和订单快照。
overlayUrl对应颜色的边框、相机与硬件覆盖层；位于用户图案之上。
maskUrl打印区域透明蒙版，不允许图案越过相机开孔和非打印区域。
previewWidth / previewHeight资源坐标基准；覆盖层、蒙版和编辑坐标必须一致。
printSpec实际打印尺寸、出血、安全区、目标像素、色彩配置和导出规则；由设备及工艺方提供。

当前预留契约：variants[colorId] = {overlay, mask, width, height}。生产环境应在此基础上加入稳定 ID、版本与 printSpec。当前代码的缺失资源回落到基础模型仅适合展示，正式环境必须禁用不存在的颜色或阻止继续，不能显示已选蓝色却仍用其他颜色外形。

  • 首次选择型号时仅展示其可用颜色；旧颜色在新机型不可用时，选定该机型默认有效颜色并提示用户。
  • 切换颜色：仅替换对应模型覆盖层及必要蒙版，保留底图、贴图、文字、层级和构图。
  • 切换机型：先预加载新资源；保留归一化坐标、缩放和旋转。不同打印区域可能产生裁切，必须重新裁剪并提示检查，禁止静默丢失用户图层。
  • 快速连续切换时只应用最后一次选择，旧请求不得覆盖新状态；资源加载失败保持旧有效模型并允许重试。
  • 设计页右上角通过轻量弹窗切换机型与颜色；取消不写入。颜色改变需同步到预览、草稿封面、作品详情、复用副本、打印稿和订单摘要。
  • 订单创建时冻结 modelId、colorId、variantId、assetVersion 及资源引用。之后后台更换资源不得悄悄改变已支付订单的打印内容。
型号 iPhone A→颜色 Blue→对应 variant 资源→编辑画布与裁剪→设计版本和封面→订单快照与打印文件

建议资源校验：同一变体图层等尺寸、透明通道有效、打印区域非空、文件可访问；后台发布前生成预览并人工确认。不得通过前端猜测相机布局。

4 设计编辑器与 AI 创作

模块交互与规则
画布移动端尽量一屏完成；上方画布，下方 Base / Stickers / Text 工具区；PC 画布在左、工具在右。全屏、关闭面板、撤销重做建议实现；关闭工具不清空设计。
底图模板、自己照片、AI 图三选一作为底图来源，可更换。模板入口须始终可切换；只替换底图，保留用户叠加内容，破坏性变更需提示。
图层贴图与文字可添加、选中、移动、缩放、旋转、删除；文字支持内容、字体、颜色、样式和对齐。工具关闭按钮明确；操作反馈不挤占画布。
照片支持 JPG / PNG / WebP；校验真实格式、体积、尺寸、损坏文件、EXIF旋转；正式上传限制由服务端配置。替换照片不复用旧上传状态。
预览渲染次序：背景 → 用户图层 → 打印区域裁剪 → 对应机型颜色覆盖层。预览外形层不混入最终打印图。
AI入口先上传照片，再选人像、宠物、情侣、旅行等分类及其风格；分类和风格从后台配置。原“任务”按当前内容定义为创作分类。
AI结果生成后显示结果；左侧再生成一次，右侧使用AI图。应用后作为底图继续DIY；结果与原图可对比，分界拖拽有明显手柄和提示，全屏与对比按钮叠放预览上。

正式 AI 任务必须由服务端创建：上传完成 → 参数校验与额度检查 → 排队 → 运行 → 成功 / 失败 / 取消。使用任务ID轮询或订阅状态；页面恢复可继续查询。进度未知时显示阶段和不确定进度，不使用固定计时器伪装真实百分比。

  • 生成失败和取消按业务约定退还冻结额度；相同请求幂等，重试不得重复扣费。注册赠送次数目前展示为5次，正式规则后台配置并通过账本管理。
  • 风格参考图不能作为用户生成结果返回；原图、参考图、生成结果明确区分。AI原图非默认公开内容，公开分享仅使用用户确认的当前作品。
  • 文字字体需有商用及打印授权；输出时字体嵌入或转轮廓，避免服务器与设备字体差异。图片分辨率不足在预览前提示。

5 账户草稿与公共作品

  • 登录：邮箱验证码、Google、Facebook 快捷登录。真实 OAuth 需服务端回调校验；验证码限流、防重放、过期及错误提示。首次成功验证创建账户。
  • 个人中心：头像、昵称、账户身份与AI余额；修改成功后全站同步。头像上传校验与裁切、昵称长度和审核策略由后台约束。
  • 保存前弹出隐私与分享确认，公开勾选默认不选；不勾选仍可保存私人草稿。公开说明包括作品图、作者头像昵称、机型标签，以及他人可点赞、复用和打印。保存授权版本和时间。
  • 保存成功弹窗含“查看设计草稿作品”和“去打印”。未保存离开需提示或自动恢复，不得无声丢失。
  • 我的设计展示封面、名称、作者与机型，可打开详情、继续设计或打印；公共作品中心与详情不显示打印次数。
  • 作品中心的封面、标题及卡片内容区可打开匹配ID详情；点赞按钮只点赞，不能触发跳转。详情直达、刷新与返回均应可用，兼容带 .html 和无扩展名的线上路径。
  • 仅作者可编辑原作、管理公开与撤回；他人使用生成独立副本并记录 parentDesignId。撤回后从公共库移除，已付订单保留授权范围内的交易快照。

正式系统的公共作品必须持久化到服务端，其他浏览器和其他用户可读取。当前 localStorage 的公开列表仅用于交互展示，不满足真正跨用户分享。建议公开作品审核、举报及侵权处理纳入后台。

6 订单支付与领取方式

确认打印先保存当前设计版本和打印快照，创建唯一订单号，再进入支付提交页。未登录可保留设计并引导登录，成功后返回原上下文；是否允许游客支付需项目方确认。

规则要求
金额当前展示标准打印 US$0.50 / 个，数量范围1–20；快递每单运费 US$4.00，预计3–4天送达。正式价格从服务端配置，前端不得决定应付金额。
计算总额 = 打印单价 × 数量 + 本单AI费用 + 运费。设备打印运费0；快递运费400美分，每单一次。所有金额用整数美分。AI费用不能把此前账户生成成本重复收费。
设备打印付款前选定有效设备；定位授权后按直线距离排序，拒绝或失败可手动选择纽约区域。卡片以地名、距离为主，导航打开地图路线。
快递到家必填收件人、电话、国家州城市和街道地址，邮编当前为选填；修改地址后必须重新校验保存。显示4美元运费及3–4天提示。
支付正式接入服务商，展示订单号、商品封面、型号颜色、费用明细和方式；支付成功弹窗包含查看详情和我的订单。服务商待商户确认，当前Airwallex为展示。
锁定付款成功后，领取方式、设备和收货地址只读；不能在详情页改为另一种方式。后续变更须走经批准的客服售后流程。

订单列表：封面、订单号、名称、金额、创建时间、状态、设备打印/快递邮寄标签；状态筛选至少全部、待付款、已付款、已打印。不得放通用设备地址选择模块。设备导航在该订单详情中提供。

订单详情：大图与设计名称、作者关联、型号颜色、数量、创建/支付/履约时间、付款方式、打印价、AI费用、运费、合计、设备快照或地址快照。快递新增待发货、已发货、已完成状态与物流字段；与“已打印”不同维度，不能将邮寄订单误标为到店打印。

7 订单与设备任务状态

待付款→支付处理中→已付款→设备任务排队 或 待发货→打印成功 或 已发货→完成
  • 付款以服务端验签后的回调或主动查询为准；前端跳转不等于成功。回调、创建订单、发起支付和打印任务均须有幂等键。
  • 支付失败/取消允许重新支付；超时关单与支付晚到冲突按服务商结果对账，防止重复收款或已收款无订单。
  • 支付完成生成受控打印凭证/二维码，绑定订单、设备、打印规格与次数。设备拉取签名下载地址并校验文件摘要。二维码有效期、跨设备转移和补打规则待设备方确认。
  • 正式打印成功由设备回执确认，失败可重试并记录原因。当前“标记已打印”仅为展示操作，不可直接作为正式履约凭证。
  • 设备离线、缺料、型号不支持时付款前阻止选择并提示替代点位；付款后发生异常走履约工单，不擅自改已付订单。
  • 设备状态至少维护启用、停用、在线、离线、维护；能力表限定支持的机型颜色及工艺。地图坐标与距离仅用于导航，不代表网点可用。

纽约 Midtown、Bryant Park、SoHo 等现有点位为页面展示数据，未核实为真实营业设备。上线必须替换为运营确认的地址、坐标、营业时间、设备能力和在线状态。

GET /catalog/models 及 /models/{id}/variants获取真实可用型号颜色资源。支持版本与缓存控制。
POST /uploads 与 POST /ai/jobs受限上传；后者要求登录、额度校验、幂等；GET任务状态。
POST /designs 与 PUT /designs/{id}作者权限，版本冲突检测；返回封面和版本号。

设备任务回执及后台接口单独设备身份、签名验证、任务授权，不暴露给普通用户。

建议错误码：VARIANT_UNAVAILABLE、ASSET_LOAD_FAILED、DESIGN_VERSION_CONFLICT、INSUFFICIENT_CREDITS、DEVICE_UNAVAILABLE、QUOTE_EXPIRED、PAYMENT_PENDING。返回用户可读信息与 traceId；不要把堆栈暴露到页面。

9 后台管理与正式环境要求

  • 目录后台：品牌、机型、颜色变体、模型资源校验、打印规格；模板/贴图库/字体授权和AI分类风格管理。资源发布需可回滚。
  • 运营后台：作品审核与撤回、账户与额度账本、订单查询、支付对账、设备在线状态与任务重试、物流录入、售后记录、权限及审计。
  • 安全：服务端鉴权与行级授权；私有原图和订单打印文件使用限时签名URL，公开封面独立资源；限制文件类型体积、上传频率与AI并发。图片定位等EXIF敏感元数据应移除。
  • 隐私：定位仅在主动请求后调用，拒绝可继续手选；地址和联系方式仅订单相关人员访问。账户注销、图片保留周期、公开授权与删除边界交由项目方确认。
  • 性能：大背景静态压缩图；懒加载非首屏图；动画以transform/opacity为主，减少大面积持续模糊和滚动重绘；尊重减少动态效果设置。
  • 响应式：建议覆盖320/390/430px手机与1024/1440px桌面；工具不遮挡关键按钮，弹窗不横向溢出，键盘出现时仍可提交；图标用SVG，不依赖系统字符外观。
  • 无障碍：触控区域建议≥44px，普通文本建议16px、标签不低于13–14px；键盘可操作、焦点可见、弹窗焦点限制与返回、图片替代文本。
  • 部署：开发/测试/生产隔离，业务配置与密钥分离；资源缓存加版本，监控前端异常、API错误、AI耗时、支付漏单和设备失败。浏览器本地存储只用于恢复和缓存。

10 验收清单与实施顺序

编号可执行验收场景
AC01每一种首页入口：选机型颜色后进入编辑器相应底图工具，不再次选机型，不提前选打印设备。
AC02同机型切两个真实颜色：边框和相机等硬件资源正确变化，图案文字不变；封面/草稿/订单一致。
AC03切至不支持原颜色的机型：重置为有效颜色；相机开孔正确；资源缺失禁止继续；连续切换无旧结果覆盖。
AC04保存并刷新/换设备登录：图层、模型颜色和版本恢复；私密草稿其他账号不可访问。
AC05未勾选分享仅自己可见；勾选后其他账号能看详情、点赞、复用打印；原始AI照片不公开。
AC06公共详情直接URL、刷新、卡片点击和浏览器返回均正确；点赞不跳转；无扩展名路由可打开。
AC07保存成功显示两个行动按钮；确认打印自动保存且只生成一笔订单；重复点击不重复下单。
AC08设备运费0，快递4美元每单且显示3–4天；切换方式正确更新总价；地址变更后重验。
AC09伪造前端成功不能改支付状态；真实回调重复处理不重复发任务；失败/超时可恢复。
AC10已付款详情不能修改领取方式和地址；设备回执成功才进入已打印；失败任务可追踪。
AC11移动端工具一屏优先、菜单全屏、弹窗无横向溢出；无旧浅绿色UI残留；中英文和社媒链接正确。

建议分四阶段交付：① 数据契约与真实型号颜色资源闭环；② 编辑器、账户、草稿与公共作品；③ AI和支付订单；④ 设备/物流履约、监控与上线验收。每阶段提供测试数据、接口文档与验收记录。

上线前需签字确认：型号颜色资源矩阵、工艺出血及分辨率、真实点位与库存能力、AI计费和授权、税费适用及支付商户、快递可达范围/时效口径、退款补打和分享条款。上述未定项不能由前端示例值直接推定为正式规则。
